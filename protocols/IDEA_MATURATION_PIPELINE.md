# Idea Maturation Pipeline

Purpose: convert rough ideas into mature, reusable, repository-safe artifacts.

## Core principle

Do not confuse first-response usefulness with idea maturity.

A mature idea has passed through framing, decomposition, challenge, multi-perspective review, evidence collection, assumption testing, alternative generation, synthesis, and memory classification.

## Raw idea incubation

Raw ideas may first live in `incubator/raw-ideas/` before entering this maturation pipeline.

A raw idea is not yet a claim, decision, accepted memory, protocol, or implementation plan. It preserves the user's core idea so it is not lost.

Model-captured raw ideas should preserve:

- the core idea before critique;
- the user's raw intent;
- conversation context;
- why the idea may matter later;
- what the idea is not;
- possible future development;
- open questions;
- next review trigger.

A raw idea enters the maturation pipeline only when the user asks to mature it, it reappears in later work, or it becomes relevant to a concrete repository decision.

## Maturity levels

```text
L0 — Raw Intuition
L1 — Framed Problem
L2 — First Model Interpretation
L3 — Challenged Interpretation
L4 — Multi-Model / Multi-Perspective Review
L5 — Synthesized Direction
L6 — Operational Design
L7 — Repository-Safe Artifact
L8 — Validated / Versioned Memory
```

## Default pipeline

1. Capture raw idea.
2. Frame the real problem.
3. Identify hidden assumptions.
4. Generate first architecture.
5. Challenge the architecture.
6. Ask adversarial questions.
7. Collect outside perspectives if needed.
8. Synthesize a new direction.
9. Convert into operational files.
10. Classify memory safety.
11. Promote, quarantine, or reject.

## Required end state

Every serious maturation session should end with:

```text
A. Matured Idea Summary
B. What Changed From the Starting Point
C. Key New Concepts
D. Rejected or Postponed Ideas
E. Operational Implications
F. Suggested Repository Files
G. Memory Classification
H. Next Action
```
